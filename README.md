# تطبيق دفتر — الدليل الكامل (Firebase + GitHub Pages)

هذا هو المسار المناسب لمتجركم: أنت واثنان من العمال (3 مستخدمين) تحتاجون تحديثًا فوريًا
بين الأجهزة، بدون رسوم متاجر تطبيقات، وبدون تعقيد إضافي.

- **قاعدة البيانات:** Firebase (Firestore) — تزامن فوري بين الأجهزة الثلاثة.
- **الاستضافة:** GitHub Pages — رابط مجاني يفتحه كل عامل من متصفح هاتفه.
- **التطبيق نفسه:** PWA (تطبيق ويب مثبّت) — يضيفه كل عامل لشاشة هاتفه الرئيسية
  فيعمل كأيقونة تطبيق عادية، بدون شريط متصفح ظاهر.

---

## الجزء الأول: تجهيز Firebase (قاعدة البيانات)

### 1) إنشاء المشروع
1. اذهب إلى https://console.firebase.google.com
2. اضغط **إضافة مشروع (Add project)** واختر اسمًا (مثلاً "دفتر-المتجر").
3. يمكنك تعطيل Google Analytics (غير ضروري لهذا التطبيق).

### 2) تفعيل قاعدة البيانات
1. من القائمة الجانبية: **Build → Firestore Database**
2. اضغط **Create database**
3. اختر **Start in production mode** ثم اختر أقرب موقع خادم لكم.

### 3) تفعيل تسجيل الدخول المجهول (Anonymous Auth)
هذا يمنع أي شخص عشوائي على الإنترنت من الوصول لبياناتكم حتى لو عرف رابط التطبيق.
1. من القائمة الجانبية: **Build → Authentication → Get started**
2. من تبويب **Sign-in method** فعّل **Anonymous**

### 4) ضبط قواعد الأمان (Security Rules)
من **Firestore Database → Rules** الصق التالي واضغط **Publish**:
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}
```
هذا يسمح بالقراءة والكتابة فقط لمن دخل عبر التطبيق (حتى لو دخولًا مجهولًا)، ويمنع أي
شخص خارجي وصل لرابط المشروع بالصدفة.

### 5) الحصول على إعدادات الربط (Config)
1. اضغط أيقونة الترس ⚙ بجانب "Project Overview" ثم **Project settings**
2. مرّر للأسفل إلى **Your apps** واضغط أيقونة **</>** لإضافة تطبيق ويب
3. أعطه اسمًا (مثلاً "دفتر ويب") ولا تفعّل Firebase Hosting هنا
4. سيظهر لك كائن باسم `firebaseConfig` يشبه هذا:
   ```js
   const firebaseConfig = {
     apiKey: "AIza...",
     authDomain: "daftar-xxxx.firebaseapp.com",
     projectId: "daftar-xxxx",
     storageBucket: "daftar-xxxx.appspot.com",
     messagingSenderId: "...",
     appId: "..."
   };
   ```
5. افتح ملف `src/firebase.js` في هذا المشروع، واستبدل القيم الموجودة بقيمك أنت.

> **ملاحظة عن الخصوصية:** هذه القيم ليست كلمة سر — لا بأس أن تظهر في كود عام على
> GitHub. الحماية الحقيقية هي قواعد الأمان في الخطوة 4 أعلاه.

## الجزء الثاني: النشر على GitHub Pages

### 1) رفع المشروع إلى GitHub
1. أنشئ مستودعًا (repository) جديدًا في GitHub، مثلاً باسم `daftar-app`
2. من داخل مجلد المشروع على جهازك:
   ```
   git init
   git add .
   git commit -m "أول نسخة من تطبيق دفتر"
   git branch -M main
   git remote add origin https://github.com/USERNAME/daftar-app.git
   git push -u origin main
   ```
   (استبدل `USERNAME` باسم حسابك على GitHub)

### 2) تثبيت المكتبات والنشر
```
npm install
npm run deploy
```
هذا الأمر يبني المشروع وينشره تلقائيًا على فرع `gh-pages`.

### 3) تفعيل GitHub Pages
1. في صفحة المستودع على GitHub: **Settings → Pages**
2. تحت **Branch** اختر `gh-pages` ثم **Save**
3. بعد دقيقة أو دقيقتين سيظهر رابط مثل:
   `https://USERNAME.github.io/daftar-app/`

### 4) تحديثات لاحقة
في أي وقت تريد تحديث التطبيق بعد تعديل الكود:
```
npm run deploy
```
فقط — يعيد البناء والنشر بنفس الرابط.

## الجزء الثالث: تثبيت التطبيق على هواتف العمال الثلاثة

1. افتح الرابط (`https://USERNAME.github.io/daftar-app/`) من متصفح الهاتف (Chrome
   على أندرويد، أو Safari على آيفون).
2. **على أندرويد (Chrome):** ستظهر رسالة "إضافة إلى الشاشة الرئيسية" تلقائيًا، أو
   من قائمة المتصفح (⋮) اختر **Add to Home screen**.
3. **على آيفون (Safari):** اضغط زر المشاركة (المربع مع السهم) ثم **Add to Home Screen**.
4. ستظهر أيقونة "دفتر" على الشاشة الرئيسية، وتفتح كتطبيق كامل الشاشة بدون شريط متصفح.

كرر هذه الخطوة على هاتفك وهاتفي العاملين الاثنين — الثلاثة سيرون نفس البيانات
مباشرة لحظة تسجيلها.

## أسئلة متوقعة

**هل يعمل بدون إنترنت؟**
يفتح التطبيق نفسه بدون إنترنت (محفوظ محليًا)، لكن أي عملية جديدة (دخل، مصروف، دين)
تحتاج اتصالاً لحفظها في Firebase ومزامنتها مع الأجهزة الأخرى.

**هل أحتاج حساب مطوّر أو رسوم؟**
لا شيء إطلاقًا لهذا المسار — Firebase وGitHub Pages مجانيان لهذا الحجم من الاستخدام.

**ماذا لو أردت لاحقًا نشره فعليًا على Google Play؟**
ممكن لاحقًا عبر Capacitor إن احتجت ذلك — أخبرني وسأجهز هذا المسار الإضافي وقتها.

## الدخول بالبصمة
من نافذة "دخول الأدمن"، اضغط **تفعيل البصمة لهذا الجهاز** بعد كتابة كلمة المرور
الصحيحة في الحقل. بعدها، كل ضغطة على "أدمن" من الشاشة الرئيسية تطلق البصمة مباشرة
(بلا خطوة إضافية)، وتبقى كلمة المرور متاحة كخيار احتياطي دائمًا. البصمة مرتبطة
بهذا الجهاز والمتصفح تحديدًا (تخزين محلي)، فيحتاج كل جهاز أدمن تفعيلها بشكل منفصل.
لإلغائها من جهاز ما، اضغط "إلغاء البصمة من هذا الجهاز" من نفس النافذة.
يتطلب هذا دعم WebAuthn في متصفح/واجهة الجهاز (متاح غالبًا على أندرويد وآيفون
الحديثين)؛ إن لم يكن مدعومًا تبقى كلمة المرور هي الطريقة الوحيدة.

## العمل بدون إنترنت، الصور، والنسخ الاحتياطي

**حفظ ثم رفع تلقائي:** يفعّل `src/firebase.js` التخزين المحلي الدائم في Firestore. أي عملية تُسجَّل بلا إنترنت تُحفظ على الهاتف وتُرفع تلقائيًا عند عودة الاتصال، وتظهر بعبارة "⏳ بانتظار الرفع" حتى تصل.

**آخر 50 عملية:** يحتفظ الهاتف في تخزين خاص (`src/localStore.js`) بآخر 50 عملية مرفوعة، ويحذف الأقدم بعد كل تحديث. العمليات غير المرفوعة بعد لا تُحذف أبدًا. تغيير العدد: `LOCAL_KEEP` في `src/logic.js`.
مع العمليات يُحفظ محليًا آخر إجماليات للتقارير (كاملة، وليست من الـ50 فقط) وقائمة الديون المفتوحة لنموذج السداد.

**الصور:** تُضغط على الهاتف إلى نحو 250 كيلوبايت وتُخزَّن داخل مستند العملية (حقل `image`)، فتُرفع مع العملية. ملفات PDF يُحفظ اسمها فقط.

**النسخة الاحتياطية:** الإعدادات ← نسخة احتياطية: تنزيل ملف JSON، أو استعادة منه (تُضاف السجلات كعمليات جديدة ولا يُحذف شيء).

**إضافة قسم جديد لاحقًا:** أضف اسمه في `COLLECTIONS` داخل `src/dataService.js` وشاشة له في `App.jsx`. البيانات القديمة لا تتأثر.

**ملاحظات:**
- أول تشغيل على أي هاتف يحتاج إنترنت (تسجيل الدخول المجهول وتحميل البيانات).
- زر تنزيل النسخة الاحتياطية يعمل في المتصفح وPWA. داخل تطبيق Android (Capacitor) قد يلزم إضافة إضافة `@capacitor/filesystem` و`@capacitor/share`.

## تحديث الواجهة والإصدار
- تحسين الدخول إلى لوحة الأدمن بكلمة المرور أو البصمة/التحقق الحيوي عند توفره على الجهاز.
- تغيير «إجمالي الصرف» إلى «إجمالي المصاريف» مع بطاقة حمراء فاتحة.
- جعل بطاقات تقارير الفواتير/المصاريف أكثر عمقًا ووضوحًا.
- تقليل ارتفاع شريط التقارير اليومية بنحو 30% وتقليل شريط الأزرار العلوي بنحو 20%.
- تحسين الحركة والضغط والانتقالات وإضافة دعم أفضل للتفاعل باللمس ولوحة المفاتيح.
- جعل نوافذ تأكيد الحذف والخروج وعناوينها وأزرارها باللون الأحمر.
- إصلاح طبقات نوافذ معاملات الموردين حتى تظهر نافذة «فاتورة/سلعة» و«دفع للمورد» أمام بطاقة المورد.
- إضافة معالجة واضحة لفشل حفظ معاملات الموردين.
- إصلاح تكرار محتوى الحقول في المكوّن المشترك `Field`.
- توسيع النسخ الاحتياطي ليشمل الموردين ومعاملات الموردين.

## Android APK عبر Capacitor

المشروع مجهز أيضًا كـ Capacitor. بعد تثبيت Node.js وAndroid Studio:

```bash
npm install
npm run build
npx cap add android
npx cap sync android
npx cap open android
```

ثم من Android Studio استخدم `Build > Generate Signed Bundle / APK` لإنشاء APK نهائي.
